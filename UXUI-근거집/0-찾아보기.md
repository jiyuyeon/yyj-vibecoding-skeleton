# UX/UI 근거집 찾아보기

- 목적: 화면을 만들 때 AI가 감으로 정하지 않고, 이미 정론이 된 기준을 찾아 따르기
- 근거: 닐슨 노먼 그룹(NN/g), Apple 휴먼 인터페이스 가이드라인(HIG), 구글 머티리얼, 영국 정부 디자인 시스템(GOV.UK), 베이마드 연구소(Baymard), 웹 접근성 기준(WCAG), W3C ARIA 부품 패턴, 토스 디자인 시스템(TDS), 돈 노먼, 벤 슈나이더만 같은 원 저자, 포토샵, 피그마, 프로크리에이트 공식 도움말
- 모든 줄에 직접 열어 본 출처 주소와 날짜가 있음 (조사일 2026-11-24)
- 전체를 매번 읽지 않음. 이 찾아보기에서 상황을 찾고 해당 파일의 그 줄만 읽음

## 쓰는 법 (AI가 지킬 순서)

1. 화면에 담을 기능이나 정보를 한 줄로 정함 (예: 생성 결과를 기다리는 20초, 모델 6개 중 하나 고르기)
2. 화면 골격부터: 6-기본-레이아웃에서 제품 종류와 화면 폭에 맞는 구조를 고름
3. 부품: 1~4에서 같은 상황의 줄을 찾아 "쓰는 부품과 방식"과 "하지 않을 것"을 따름
4. 이름: 부품은 7-UI-부품-이름의 이름으로 부름. 플랫폼마다 이름이 다른 것(내비게이션 바, 스테퍼, 얼럿)은 어느 쪽 뜻인지 밝힘. 쓰는 사람에게 말할 때는 쉬운 말을 앞에, 부품 이름을 괄호에
5. 점검: 5-기본-원칙과-글, 8-그-밖의-UX-이론의 "화면에서 이렇게 확인" 칸으로 확인. 근거 세기가 약한 이론은 근거로 내세우지 않음
6. 출처끼리 다른 줄은 프로젝트 매체(모바일 앱, 웹, 데스크톱)에 맞는 쪽을 고르고 한 줄로 알림
7. 목록에 없으면 NN/g, Apple HIG, 머티리얼, GOV.UK, 베이마드 순서로 찾아 같은 형식으로 해당 파일에 한 줄 더함. 근거를 못 찾은 것은 "판단"이라고 밝힘
8. AI 화면 점검은 사람 시험을 대신하지 못함 (5-기본-원칙과-글 C절). 심각도와 여러 화면에 걸친 흐름은 사람이 판정

## 찾을 거리

### 1-안내와-피드백.md

- 아이콘이나 단추 하나의 짧은 설명
- 누르면 보는 보조 설명 (? 단추, 조건 설명)
- 대부분이 알아야 결과가 잘 나오는 조건 (예 잘 나오는 사진 조건)
- 일부만 필요한 긴 도움말
- 1초 미만으로 끝나는 반응
- 2~10초 기다림 (영역 하나)
- 10초 넘는 기다림 (생성, 업로드, 변환)
- 화면 전체 처음 불러오기
- 저장 중, AI 처리 중 입력 막기
- 처리 과정 보여 주기
- 상태 문구의 접근성
- 입력 오류 위치
- 오류 문구
- 실시간 입력 검사 시점
- 시스템 실패, 심각한 오류
- 빈 화면: 처음 사용
- 빈 화면: 결과 없음
- 일상적인 성공 확인 (저장, 복사)
- 큰 과정을 끝낸 순간
- 장식 움직임 (축하, 반짝임)
- 되돌릴 수 있는 삭제나 변경
- 되돌릴 수 없는 큰 동작
- 알림 배지
- 상태 표시와 단추 구분
- 처음 쓰는 사람 안내 (튜토리얼)
- 코치마크, 기능 팁
- 실행취소와 다시 실행
- 진행 중 그만두기, 빠져나가기

### 2-입력과-고르기.md

- 하나 고르기, 선택지 2~5개
- 하나 고르기, 선택지 5~15개 또는 이름이 긴 경우
- 하나 고르기의 기본 선택
- 여러 개 고르기
- 켜고 끄기 설정
- 설정 여러 개 묶기
- 필수와 선택 표시
- 입력칸 이름과 도움말
- 오류 알리기(입력 검사 시점)
- 입력 양식 배치
- 키보드가 입력칸을 가리는 문제
- 주요 버튼 자리
- 숫자 입력
- 개수 고르기(몇 장, 몇 개)
- 파일, 그림 올리기
- 여러 단계 입력
- 다음 버튼을 언제 누를 수 있게 할지
- 입력 방식 바꾸기(예: 파일 올리기와 글로 만들기)
- 고른 옵션 때문에 다른 칸을 못 쓸 때
- 검색 입력
- 검색 결과 좁히기(필터)
- 누름 영역 크기

### 3-화면-구조와-이동.md

- 지금 화면을 보면서 하는 짧은 선택이나 입력
- 바텀시트 닫기와 높이 조절
- 시트 안에서 또 시트가 필요할 때
- 복잡하거나 오래 걸리는 작업(편집, 여러 단계)
- 하던 일을 멈추고 꼭 답해야 하는 순간
- 버튼 하나로 끝나는 단순 선택
- 넓은 화면에서 보조 정보나 필터
- 누른 자리 옆에 잠깐 띄우는 작은 메뉴나 정보
- 툴팁, 팝오버가 상자 밖으로 잘림
- 툴팁에 넣을 내용
- 한 화면 안에서 관련 있는 보기 전환
- 세그먼트 컨트롤 쓰는 법
- 서로 다른 내용으로 가는 이동
- 펼침 목록(아코디언)
- 여러 단계 깊이의 구조에서 현재 위치
- 모바일 앱의 큰 구역 이동
- 넓은 화면, 구역이 많은 앱
- 숨은 메뉴(햄버거 버튼)
- 비슷한 항목 여러 개를 찾고 고르기
- 종류가 섞인 내용 모음(대시보드)
- 속성이 많은 데이터 비교
- 계속 늘어나는 모음(목록이 김)
- 가로로 넘기는 줄(캐러셀)
- 필터
- 정렬 기본값과 기억
- 기간 단위 화면(주, 월)
- 목록 관리(삭제, 순서 바꾸기, 여러 개 고르기)
- 넓은 화면의 글 읽기
- 내용이 늦게 들어오거나 바뀔 때 칸이 밀림
- 불러오는 동안 보여 줄 것

### 5-기본-원칙과-글.md

- A-1. 닐슨 사용성 10원칙: 1 시스템 상태 보여 주기, 2 현실 세계와 맞추기, 3 사용자 통제와 자유, 4 일관성과 표준, 5 오류 예방, 6 기억보다 알아보기, 7 유연성과 효율, 8 미적이고 최소한의 디자인, 9 오류 인식, 진단, 복구 돕기, 10 도움말과 문서
- A-2. 심리 법칙과 게슈탈트: 피츠의 법칙, 힉의 법칙, 제이콥의 법칙, 밀러와 덩어리 짓기, 보기 좋으면 쓰기 쉽다고 느낌, 순서 위치 효과, 근접, 유사, 공통 영역
- A-3. 시각 위계, 단계적 공개, 알아보기, 관례: 시각 위계, 주요 버튼 한두 개, 버튼 위계, 단계적 공개, 기억보다 알아보기, 일관성과 관례
- A-4. 읽기, 대비, 누름 영역: 본문 크기, 앱 기본 글자, 줄 길이와 줄 간격, 덩어리 글, 글자 대비 4.5:1, 다크 모드 대비, 누름 영역 (웹 최소), 누름 영역 (iOS), 누름 영역 (안드로이드), 누름 영역 (실제 크기)
- A-5. 움직임과 다크 모드: 움직임 길이, 움직임 시간 값, 움직임 줄이기 (웹), 움직임 줄이기 (기준), 움직임 줄이기 (iOS), 다크 모드 역할 색, 다크 모드 (안드로이드), 다크 모드 표면, 다크 모드 기본값
- B-1. 토스 라이팅 원칙 8가지: 다음 화면 예고 (Predictable hint), 잡초 뽑기 (Weed cutting), 빈 문장 제거, 핵심 메시지 집중, 말하듯 쉽게, 강요 대신 권유, 누구나 이해하는 말, 숨은 감정 찾기
- B-2. NN/g 글쓰기 기준: 버튼은 결과를 말하는 동사, 버튼 동사 (Apple), 마이크로카피 3I, 오류 문구 보이기, 오류 문구 말하기, 오류 문구 효율, 쉬운 말, 짧고 훑어보기 쉽게, F자 패턴과 앞에 두기
- B-3. 한국어 공공 쉬운 말: 쉬운 공공언어, 쉬운 말보다 쉬운 서비스, 공공 UX 라이팅 5원칙 (민간 가이드)
