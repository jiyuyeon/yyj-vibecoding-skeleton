# UX/UI 근거집 찾아보기

- 목적: 기능이나 정보를 화면에 담을 때 AI가 스스로 판단해 부품을 고르지 않고, 이미 정론이 된 기준을 찾아 따르기
- 근거: 닐슨 노먼 그룹(NN/g), Apple 휴먼 인터페이스 가이드라인(HIG), 구글 머티리얼, 영국 정부 디자인 시스템(GOV.UK), 베이마드 연구소(Baymard), 웹 접근성 기준(WCAG), 토스 디자인 시스템(TDS), 포토샵, 피그마, 프로크리에이트 공식 도움말
- 조사일: 2026-11-24. 모든 줄에 직접 열어 본 출처 주소와 날짜가 있음
- 크기: 전체 약 13만 자. 매번 다 읽지 않고 이 찾아보기에서 상황을 찾은 뒤 해당 파일의 그 줄만 읽음

## 쓰는 법 (AI가 지킬 순서)

1. 화면에 넣을 기능이나 정보가 무엇인지 한 줄로 정함 (예: 생성 결과를 기다리는 20초, 모델 6개 중 하나 고르기)
2. 아래 목록에서 같은 상황을 찾고, 그 파일에서 상황 이름으로 줄을 찾아 "쓰는 부품과 방식"과 "하지 않을 것"을 따름
3. 출처끼리 다른 줄은 그 줄의 엇갈림 설명과 프로젝트 매체(모바일 앱, 웹, 데스크톱)에 맞는 쪽을 고르고, 보고에 한 줄로 알림
4. 목록에 없는 상황이면 NN/g, Apple HIG, 머티리얼, GOV.UK, Baymard 순서로 찾아 같은 형식(상황, 부품과 방식, 하지 않을 것, 근거 요지, 출처 주소와 날짜)으로 해당 파일에 한 줄을 더함
5. 근거를 못 찾은 판단은 "판단"이라고 적고, 근거가 있는 것처럼 쓰지 않음
6. 화면 점검 때 고른 부품마다 근거 줄을 짝지어 보고함 (UICrit 2024 연구: 지침과 사람의 비평 예시를 함께 줄 때 AI 점검이 나아지지만 사람보다는 정확도가 낮음. 심각도와 여러 화면에 걸친 흐름은 사람이 판정)

### 1-안내와-피드백.md

- 아이콘이나 단추 하나의 짧은 설명
- 누르면 보는 보조 설명 (? 단추, 조건 설명)
- 대부분이 알아야 결과가 잘 나오는 조건 (예 잘 나오는 사진 조건)
- 일부만 필요한 긴 도움말
- 1초 미만으로 끝나는 반응
- 2~10초 기다림 (영역 하나)
- 10초 넘는 기다림 (생성, 업로드, 변환)
- 화면 전체 처음 불러오기
- 저장 중, AI 처리 중 입력 막기
- 처리 과정 보여 주기
- 상태 문구의 접근성
- 입력 오류 위치
- 오류 문구
- 실시간 입력 검사 시점
- 시스템 실패, 심각한 오류
- 빈 화면: 처음 사용
- 빈 화면: 결과 없음
- 일상적인 성공 확인 (저장, 복사)
- 큰 과정을 끝낸 순간
- 장식 움직임 (축하, 반짝임)
- 되돌릴 수 있는 삭제나 변경
- 되돌릴 수 없는 큰 동작
- 알림 배지
- 상태 표시와 단추 구분
- 처음 쓰는 사람 안내 (튜토리얼)
- 코치마크, 기능 팁
- 실행취소와 다시 실행
- 진행 중 그만두기, 빠져나가기

### 3-화면-구조와-이동.md

- 지금 화면을 보면서 하는 짧은 선택이나 입력
- 바텀시트 닫기와 높이 조절
- 시트 안에서 또 시트가 필요할 때
- 복잡하거나 오래 걸리는 작업(편집, 여러 단계)
- 하던 일을 멈추고 꼭 답해야 하는 순간
- 버튼 하나로 끝나는 단순 선택
- 넓은 화면에서 보조 정보나 필터
- 누른 자리 옆에 잠깐 띄우는 작은 메뉴나 정보
- 툴팁, 팝오버가 상자 밖으로 잘림
- 툴팁에 넣을 내용
- 한 화면 안에서 관련 있는 보기 전환
- 세그먼트 컨트롤 쓰는 법
- 서로 다른 내용으로 가는 이동
- 펼침 목록(아코디언)
- 여러 단계 깊이의 구조에서 현재 위치
- 모바일 앱의 큰 구역 이동
- 넓은 화면, 구역이 많은 앱
- 숨은 메뉴(햄버거 버튼)
- 비슷한 항목 여러 개를 찾고 고르기
- 종류가 섞인 내용 모음(대시보드)
- 속성이 많은 데이터 비교
- 계속 늘어나는 모음(목록이 김)
- 가로로 넘기는 줄(캐러셀)
- 필터
- 정렬 기본값과 기억
- 기간 단위 화면(주, 월)
- 목록 관리(삭제, 순서 바꾸기, 여러 개 고르기)
- 넓은 화면의 글 읽기
- 내용이 늦게 들어오거나 바뀔 때 칸이 밀림
- 불러오는 동안 보여 줄 것
